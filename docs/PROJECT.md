# Опис курсового проєкту

**Назва:** Analytics Ticket Copilot  
**Індустрія (таблиця Андрія):** IT / розробка — Jira-тікети, аналіз багів  
**Автор:** курс AI Engineering, потік 2

## Ідея

Сервіс для команди аналітичної звітності, яка підтримує ланцюг:

```
SAP Fiori
  → Databricks (таблиці / marts)
    → Parent semantic model (живлення з Databricks)
      → Child model (DirectQuery до parent + власна логіка)
        → RDL / Power BI report (дизайн і build звіту)
```

У будь-якій ланці можуть бути причини бага або change request. Система допомагає:
витягнути структуру з «брудного» Jira-тексту, знайти схожі кейси й спеку,
локалізувати шар проблеми й залишити зрозумілий коментар у тікеті.

**Для кого:** report developer, Data Pull, financial analyst (власник специфікації).

## Дані

| Що | Де |
|----|-----|
| Сирі тексти | Jira-проєкт `BUGS` — експорт у `data/raw/` (53 тікети) |
| Golden set | 10 вручну розмічених: `BUGS-41`…`BUGS-50` → `data/golden.json` |
| Довідники | `data/reference/` — команди, звіти, pipeline, деплой |
| Мови | українська / російська / англійська впереміш, опечатки, пропуски |

Далі корпус можна розширити спеками (SPEC-*) і короткими описами моделей
(parent / child / RDL) — для RAG і агента.

## Чотири етапи курсу

1. **Extraction (кейс 1, зараз):** з Jira-тексту → валідний JSON (тип, пріоритет, звіт,
   SAP, спека, ролі, сверки, деплой DEV→approval→PROD); порівняння Gemini vs локальні моделі.
2. **RAG:** пошук по тікетах, спеках і довідниках; відповідь з посиланням на джерело.
3. **Агент:** аналіз бага → сверка зі спекою → локалізація ланки
   (RDL / child / parent / Databricks / SAP) → чернетка фіксу + коментар у Jira.
4. **Сервіс:** API, захист, моніторинг, облік вартості токенів; Demo Day.
